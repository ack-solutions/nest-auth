## Summary

`apps/docs/scripts/build-sql-snapshots.ts` writes placeholder text into `apps/docs/public/sql/{postgres,mysql,sqlite}.sql` instead of actually generating CREATE TABLE statements from the TypeORM entity metadata. The "copy-paste SQL" path on the [Database Setup](https://ack-solutions.github.io/nest-auth/docs/getting-started/database-setup/) page therefore links to files like:

```
-- postgres schema for @ackplus/nest-auth
-- Generated by apps/docs/scripts/build-sql-snapshots.ts
-- TODO: implement TypeORM SchemaBuilder export.
```

## Where

`apps/docs/scripts/build-sql-snapshots.ts:13-37`

## Impact

The third install path documented in [Database Setup](apps/docs/content/docs/getting-started/database-setup.mdx) — "for users who do not want TypeORM CLI to manage migrations" — is currently broken. A user who clicks `/sql/postgres.sql` gets a stub.

## Fix hypothesis

Use TypeORM's `DataSource` + `SchemaBuilder.log()` pattern:

```ts
import { DataSource } from 'typeorm';
import { NestAuthEntities } from '@ackplus/nest-auth';

for (const dialect of ['postgres', 'mysql', 'sqlite'] as const) {
  const ds = new DataSource({
    type: dialect,
    entities: [...NestAuthEntities],
    // dialect-specific options (sqlite needs a database path)
  });
  await ds.initialize();
  const queries = await ds.driver.createSchemaBuilder().log();
  const sql = queries.upQueries.map(q => q.query + ';').join('\n');
  writeFileSync(resolve(outDir, `${dialect}.sql`), sql);
  await ds.destroy();
}
```

Note: `mysql` and `postgres` drivers don't need a live connection for `log()`, but `sqlite` does — pass a temp `:memory:` database.
