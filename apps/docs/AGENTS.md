# AGENTS.md — `apps/docs`

> Fumadocs-powered Next.js docs site. Static-export to `apps/docs/out/`. Deployed to GitHub Pages.

## Stack

- **Next.js 15** (App Router, `output: 'export'`)
- **Fumadocs UI 14** + **Fumadocs MDX**
- **TypeDoc** for the auto-generated TypeScript reference
- **Custom OpenAPI renderer** in `components/endpoint-docs.tsx` (the installed `fumadocs-openapi@5.12` requires Fumadocs UI 15 — version mismatch, so we render endpoints ourselves)

## Build pipeline

`pnpm build` (the `@ackplus/nest-auth-docs` script):

1. `build:generate` — runs in this order:
   - `generate:typedoc` → writes `public/typedoc.json` from `packages/*/src/index.ts`
   - `generate:sql` → writes `public/sql/{postgres,mysql,sqlite}.sql` (currently stub output — see issue)
   - `generate:openapi-pages` → reads `public/api/nest-auth.json` and emits 30 MDX files into `content/docs/api-reference/(generated)/`
2. `next build` — produces static export at `apps/docs/out/`

Run individually: `pnpm generate:typedoc`, `pnpm generate:openapi-pages`, `pnpm generate:sql`. The OpenAPI export script (`build-openapi.ts`) is run separately when wired up.

## Conventions

- **basePath awareness.** Set in `next.config.mjs` to `/nest-auth` in production. Internal links use `<Link>` (auto-prepended). MDX `[text](/foo)` links go through `MdxLink` shim. `fetch()` URLs need `${process.env.NEXT_PUBLIC_BASE_PATH}` prefix manually. The search route handler URL is in `app/layout.tsx`.
- **Search type must be `'static'`.** Default is `'fetch'` which expects a server route under `output: 'export'`; that doesn't work. Configured in `app/layout.tsx`.
- **Frontmatter with backticks must be quoted.** YAML doesn't tolerate unquoted strings starting with backtick. Use `description: 'foo `bar` baz'`.
- **Custom MDX `<a>`.** Registered in `app/docs/[[...slug]]/page.tsx`. If you add another MDX renderer (e.g. for the home page), wire `MdxLink` in.
- **Auto-generated tree.** Don't hand-edit anything under `content/docs/api-reference/(generated)/`. The `build-openapi-pages.ts` script wipes and recreates it.
- **Tag the search index.** New top-level sections need an entry in `app/api/search/route.ts → SECTION_TAG_MAP` so search filtering works.

## Deployment

`.github/workflows/docs.yml` builds on push to `main`, deploys to GitHub Pages via `actions/deploy-pages@v4`. Pages must be enabled with **Source: GitHub Actions** in the repo settings (one-time).

## Common edits

| You want to … | Touch |
| --- | --- |
| Add a doc page | `content/docs/<section>/<slug>.mdx` + the section's `meta.json` |
| Change sidebar order | The relevant `meta.json` |
| Add a code component | `components/<name>.tsx`, then register in `app/docs/[[...slug]]/page.tsx` MDX `components` |
| Update the home page | `app/(home)/page.tsx` + `page.module.css` |
| Change OpenAPI rendering | `components/endpoint-docs.tsx` (re-runs only when you re-build; if you change the *spec*, also re-run `pnpm generate:openapi-pages`) |
| Refresh TypeDoc | `pnpm generate:typedoc` |
| Add quick-search links | `QUICK_LINKS` in `app/layout.tsx` |
