Each recipe is a self-contained, runnable example. Pick one, copy the code, adapt the names — done.

### Auth lifecycle & events

- [React to a new signup with `UserRegisteredEvent`](/docs/recipes/user-registered-listener) — create your `AppUser`, link a referral, queue a welcome email.
- [React to login with `UserLoggedInEvent`](/docs/recipes/user-logged-in-listener) — last-login tracking, role sync, audit writes.
- [Transactional user creation](/docs/recipes/transactional-user-creation) — wrap `NestAuthUser` + `AppUser` in one TypeORM transaction so a mid-flow failure rolls back cleanly.
- [Custom OAuth provider](/docs/recipes/custom-oauth-provider) — extend `BaseAuthProvider` for an IDP that isn't built in.
- [Extra signup fields with `collectProfileFields`](/docs/recipes/extra-signup-fields) — capture and persist your own fields at registration.
- [Link multiple providers to one account](/docs/recipes/link-multiple-providers) — connect Google, Apple, password, etc. under a single identity.
- [Normalize email & phone](/docs/recipes/normalize-email-phone) — `normalizedEmail` / `normalizedPhone` for consistent identity matching.

### Multi-tenant & multi-platform

- [Multi-platform login with guards](/docs/recipes/multi-platform-login) — admin / portal / mobile from one backend, with origin-aware login gating.
- [Platform-admin portal](/docs/recipes/platform-admin-portal) — staff who manage the whole platform as full users with a cross-tenant super-admin role, origin-locked and MFA-gated.
- [Tenant switcher](/docs/recipes/tenant-switcher) — a tenant-picker dropdown that re-scopes the active session.
- [Logging in under a tenant (ISOLATED)](/docs/recipes/tenant-login-isolated) — slug → `tenantId` resolution, the login DTO, password reset, and the invite pattern.
- [Per-request config (mobile vs web)](/docs/recipes/per-request-config) — vary auth behavior per incoming request.

### Multi-account switcher (v2.6)

**New in v2.6:** nest-auth is multi-session by design — each login mints an independent session, so one client can hold several account token sets at once.

- [Multi-account login & switching](/docs/recipes/multi-account-switching) — Gmail/Slack-style account switching in header or cookie mode.
