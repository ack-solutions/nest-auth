`AuthClient` is the framework-agnostic JS/TS client. Construct it once per app — typically as a module-level singleton.

```ts
import { AuthClient } from '@ackplus/nest-auth-client';

export const auth = new AuthClient({
  baseUrl: 'https://api.example.com',
});
```

For the constructor options, see [Config](/docs/client/config).

## Auth flows

### `login(dto, options?) => Promise<IAuthResponse>`

Logs the user in. Sets tokens (header or cookie mode) and persists the session locally.

```ts
await auth.login({
  credentials: { email, password },
});

// Or with explicit provider:
await auth.login({
  providerName: 'google',
  credentials: { token: googleIdToken },
});
```

For social sign-in there's also `socialLogin(provider, token, opts?)`. Apple only returns the user's name on the **first** authorization, so forward it (and, if you have one, an avatar) via the credential options — the backend persists them:

```ts
await auth.socialLogin('apple', identityToken, {
  nonce,
  firstName: 'Ada',
  lastName: 'Lovelace',
  // avatarUrl is optional — Apple provides none; Google falls back to its own picture.
});
```

If MFA is required, the response carries `isRequiresMfa: true` and the client holds a one-shot challenge token. Call `send2fa` and `verify2fa` to complete.

### `signup(dto, options?) => Promise<IAuthResponse>`

```ts
await auth.signup({
  email: 'alice@example.com',
  password: '…',
  // any extra fields land on UserRegisteredEvent
  firstName: 'Alice',
});
```

By default users are auto-logged-in after signup. Set `registration.autoLoginAfterSignup: false` server-side to disable.

### `passwordlessSend(dto, options?) => Promise<IMessageResponse>`

Sends a passwordless login code:

```ts
await auth.passwordlessSend({ identifier: email, channel: 'email' });
```

### `logout(options?) => Promise<void>`

Revokes the current session and clears local tokens. Fires the `logout` event.

### `logoutAll(options?) => Promise<IMessageResponse>`

Revokes every session for the user across all devices.

### `refresh(dto?, options?) => Promise<ITokenPair | null>`

Manually refresh tokens. In cookie mode, returns `null` (the new cookie is set automatically).

You usually don't need to call this — the auto-refresh path handles it.

## Sessions & user

### `verifySession(options?) => Promise<{ valid; userId?; expiresAt? }>`

Lightweight session check — useful in `<AuthGuard>`-style components or middleware.

### `getSessionUserData() => Promise<ISessionUserData>`

Returns the full user data (the same payload `useUser()` exposes in React).

### `getClientConfig(options?) => Promise<IClientConfig>`

Fetch the backend's **public** config (no auth): tenant mode, email/phone/passwordless flags, OAuth public client/app ids, registration/MFA options, `platformAccess.enabled`, `accessTokenType`, and `multipleAccounts.enabled`. Use it to adapt login/signup UI to the backend.

```ts
const cfg = await auth.getClientConfig();
if (cfg.passwordless?.enabled) { /* show OTP login */ }
if (cfg.google?.enabled) { /* show Google button with cfg.google.clientId */ }
if (cfg.multipleAccounts?.enabled) { /* show switcher */ }
```

### `switchTenant(dto, options?) => Promise<IAuthResponse>`

Swap the active tenant. Returns a fresh session bound to the new tenant.

```ts
await auth.switchTenant({ tenantId: 'tenant-acme' });
```

## Password management

| Method | Purpose |
|---|---|
| `forgotPassword(dto)` | Initiate reset (server emits event with code) |
| `verifyForgotPasswordOtp(dto)` | Trade the code for a `resetToken` |
| `resetPassword(dto)` | Final reset using the token |
| `changePassword(dto)` | Authenticated change with old password |

| Method | Purpose |
|---|---|

| `verifyEmail(dto)` | Verify with the code |
| `sendPhoneVerification(dto?)` | Send an SMS code |
| `verifyPhone(dto)` | Verify with the code |

## MFA

| Method | Purpose |
|---|---|
| `send2fa(method?)` | Send the email/SMS challenge |
| `verify2fa(dto)` | Complete the MFA step |
| `setupTotp()` | Get TOTP secret + QR code data URL |
| `verifyTotpSetup(dto)` | Finalize TOTP enrollment |
| `getMfaStatus()` | Status — configured/verified methods, devices, recovery code |
| `listTotpDevices()` / `removeTotpDevice(deviceId)` | TOTP device management |
| `toggleMfa(dto)` | Enable/disable MFA |
| `generateRecoveryCode()` | Issue a recovery code (returned **once**) |
| `resetMfa(code)` | Reset all MFA using a recovery code |

## HTTP-client wiring

Make your **own** axios/fetch share this client's auth state — attach auth headers automatically and retry once on 401 after refresh.

| Method | Purpose |
|---|---|
| `attachToAxios(instance, opts?)` | Wire an axios instance; returns an unsubscribe to eject the interceptors |
| `attachToFetch(baseFetch?, opts?)` | Wrap a `fetch` (defaults to `globalThis.fetch`); returns a new fetch-shaped function |

```ts
const detach = auth.attachToAxios(api);
const myFetch = auth.attachToFetch();
```

Options (`retryOn401`, `skipPaths`, `onRefreshFailed`) and the active-account-following pattern are in [HTTP adapters](/docs/client/http-adapters).

## Events

Every method below returns an unsubscribe function:

| Method | Fires when |
|---|---|
| `onTokenRefreshed(cb)` | Auto-refresh succeeds |
| `onTokensSet(cb)` | Tokens are stored (login/signup/refresh) |
| `onTokensRemoved(cb)` | Tokens are cleared (logout) |
| `onLogout(cb)` | Logout completes |
| `onError(cb)` | Any auth error |
| `onSessionVerified(cb)` | A `verifySession` call succeeded |
| `onRefreshSessionData(cb)` | The session data should be refetched |

## Multi-account (account switcher)

For logging into several accounts on one client and switching the active one (requires `session.allowMultipleAccounts` on the backend). Two managers, one shared `IAccountSwitcher` interface:

| Class | Mode | How it works |
|---|---|---|
| `AccountManager` | **header** | One `AuthClient` per account with its own namespaced storage; switch = repoint active (no server call) |
| `CookieAccountManager` | **cookie** | Server holds per-account httpOnly cookies + a non-httpOnly selector; switch = rewrite the selector cookie (browser-only) |

```ts
import { AccountManager } from '@ackplus/nest-auth-client';

const accounts = new AccountManager({ baseUrl, accessTokenType: 'header' });
await accounts.addAccount({ providerName: 'email', credentials: { email, password } });
await accounts.switchAccount(id);          // no network
const headers = await accounts.getAuthHeaders();   // for the ACTIVE account
accounts.listAccounts();                   // [{ accountId, email, isActive }, …]
```

Common surface: `ready()`, `listAccounts()`, `getActiveAccountId()`, `getActiveClient()`, `addAccount()`, `switchAccount()`, `removeAccount()`, `subscribe()`. Full walkthrough (incl. cookie mode + React): [Multi-account login & switching](/docs/recipes/multi-account-switching).
